## Лаба 1 — «Фургон кави»

Фургон заданого об'єму завантажується кавою на задану суму. Кава буває в зернах, мелена та розчинна (у банках або пакетиках), а об'єм і вага враховуються разом з упаковкою.

**Що вміє програма:**
- завантажує фургон з урахуванням його об'єму та бюджету;
- сортує товари за співвідношенням ціни до ваги;
- шукає каву в заданому діапазоні якості.

**Особливості:**
- ієрархія `Coffee` → `CoffeeBeans`, `GroundCoffee`, `InstantCoffee`; обсмаження, помол і упаковка задані через enum;
- асортимент і параметри фургона читаються з файлів `coffee.csv` і `van.properties`;
- усі вхідні дані перевіряються; якщо рядок у CSV некоректний, повідомлення вказує його номер;
- unit-тести на JUnit 5 і Mockito, звіт покриття JaCoCo.

**Структура:**
```
lab1/src/main/java/app/coffee/
├── Main.java, CoffeeVanApp.java   — точка входу та сценарій роботи
├── model/                         — кава, enum-и, фургон
└── service/                       — завантаження даних, операції з фургоном
```

**Запуск** (потрібні JDK 17+ і Maven):
```bash
cd lab1
mvn test                                                  # тести + звіт target/site/jacoco
mvn compile exec:java -Dexec.mainClass=app.coffee.Main    # запуск програми
```

## Лаба 2 — «Концерти танцювального колективу»

Опис танцювальних номерів концерту в XML: напрямок танцю, сцена, кількість виконавців, музичний супровід, танцюристи та номер у програмі.

**Що вміє програма:**
- перевіряє `dances.xml` за схемою `dance.xsd`;
- розбирає документ трьома парсерами (DOM, SAX і StAX) і переконується, що результати однакові;
- сортує танці через `Comparator` за номером у програмі, напрямком танцю або id;
- XSL-перетворенням групує танці за напрямком.

**Особливості:**
- XSD містить прості та комплексні типи, переліки, граничні значення, обов'язкові атрибути та `xs:ID`;
- три парсери спільно використовують `DanceBuilder`, тому код не дублюється;
- логування налаштоване через `java.util.logging` і `logging.properties`;
- unit-тести, звіт покриття JaCoCo.

**Структура:**
```
lab2/src/main/
├── java/com/dance/
│   ├── model/      — Dance, Dancer, компаратори
│   ├── parser/     — DOM, SAX, StAX і спільний DanceBuilder
│   ├── service/    — валідація XSD та XSL-перетворення
│   └── config/     — налаштування логера
└── resources/      — dances.xml, dance.xsd, transform.xsl, logging.properties
```

**Запуск** (потрібні JDK 17+ і Maven):
```bash
cd lab2
mvn test                                                  # тести + звіт target/site/jacoco
mvn compile exec:java -Dexec.mainClass=com.dance.Main     # запуск програми
```
Результат XSL-перетворення записується у файл `lab2/target/dances_transformed.xml`.

## Лаба 3 — «Морський бій»

Android-гра, у якій людина грає проти комп'ютера на полях 10×10 з класичним флотом.

**Можливості:**
- головне меню з кнопками «Нова гра», «Продовжити гру» і «Як грати»;
- ручна розстановка флоту: вибір корабля й напрямку, підказки, пояснення, чому корабель не вміщується, а також кнопки «Випадково» й «Очистити»;
- бій: хто влучив, той стріляє ще раз; навколо потопленого корабля клітинки позначаються автоматично; останній постріл підсвічено;
- комп'ютер шукає кораблі в шаховому порядку й добиває поранені;
- екран з правилами та поясненням позначок;
- обидва поля видно одночасно, в альбомній орієнтації вони стоять поруч.

**Технічні вимоги:**
- **i18n:** українська та англійська через `strings.xml`, включно з формами множини й літерами стовпців (А–К / A–J). Мову можна перемкнути в застосунку, а на Android 13+ також у системних налаштуваннях. Вибір мови зберігається.
- **Логування:** Timber. У debug-збірці пише всі рівні, у release лише попередження й помилки.
- **Архітектура:** логіка гри (`game/`) окремо від інтерфейсу (`ui/`); стан тримає ViewModel, тому партія не скидається при повороті екрана чи зміні мови.
- **Тести:** unit-тести логіки гри, ходів комп'ютера та ViewModel.

**Структура:**
```
lab3/app/src/main/
├── java/com/kuts/battleship/
│   ├── game/       — поле, кораблі, розстановка, комп'ютер, правила ходів
│   ├── ui/         — екрани Compose і GameViewModel
│   └── logging/    — дерево Timber для release
└── res/            — values/ (en), values-uk/ (uk), locales_config.xml
```

**Запуск** (потрібна Android Studio):
1. **File → Open** і вибрати папку `lab3`, дочекатися Gradle Sync.
2. Вибрати конфігурацію `app` та емулятор або телефон.
3. Натиснути ▶ **Run**.

Тести з командного рядка:
```bash
cd lab3
./gradlew testDebugUnitTest
```
